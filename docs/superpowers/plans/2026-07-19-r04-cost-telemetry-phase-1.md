# R04 Cost/Token Telemetry Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Capture accurate immutable usage facts for graph executions, expose graph-run cost/token rollups, make unmatched rates machine-visible, and rotate the JSONL recovery journal without weakening recovery.

**Architecture:** Perform the full internal Python vocabulary cutover mechanically with a tested LibCST codemod while preserving provider wire keys at parser boundaries. Treat `ModelTokenUsage` as one immutable execution-by-model fact, persist graph usage as idempotent `node_usage_recorded` events, and derive graph rollups from those events rather than joining run totals to node metadata. Rotate the JSONL journal into position-ranged segments and replay every segment during bootstrap and restore.

**Tech Stack:** Python 3.12, Pydantic v2, SQLAlchemy 2.0 async, Alembic, FastAPI, LibCST, pytest, React/TypeScript.

## Design Corrections

This plan supersedes contradictory details in `docs/superpowers/specs/2026-07-19-r04-cost-telemetry-phase-1-design.md`:

- `ModelTokenUsage` means one immutable **execution x model** fact, not one provider API call. Current runners cannot preserve true provider-call identity.
- Persist `gen_ai_response_finish_reasons: list[str]`, matching OTel's plural attribute.
- Full rename means all internal accounting contracts use OTel names. Provider wire keys such as `inputTokens`, `input_tokens`, and `reasoningOutputTokens` remain unchanged only inside boundary parsers.
- Python renames are generated by a tested LibCST codemod. TypeScript, migrations, SQL strings, and persisted JSON are handled by explicit bounded steps.
- Drop flat token columns from both `runs` and `attempts`; rename retained `cost_records` token columns to canonical names.
- Migrate existing usage JSON and event payloads; do not silently deserialize historical values as zero.
- `node_usage_recorded` includes `execution_id`, `usage_index`, `usage_count`, and `profile`. Its stable identity is `<execution_id>:<usage_index>`.
- Graph usage events are authoritative. Run totals are derived projections, not a second independently committed write.
- The rollup is graph-only in phase 1 and reads `node_usage_recorded` facts. `day` is the UTC event day and time bounds are half-open: `from <= timestamp < to`.
- Journal archives remain recovery inputs. Rotation bounds active-segment size and in-memory tracking, not total disk usage.

## Global Constraints

- Use TDD for every behavior change: add a failing test, verify the expected failure, implement minimally, and verify green.
- Do not use `patch`, `MagicMock`, or monkeypatch. Use real models, in-memory SQLite, real temporary files, injected clocks, and injected monotonic timers.
- Use `uv run` for every Python command.
- Import cross-module symbols only from the nine public top-level module APIs.
- Do not add an OpenTelemetry runtime/exporter dependency in phase 1.
- Preserve provider wire formats at runner parser boundaries.
- Do not maintain independent run and graph-event usage writes; event persistence and projections must remain transactionally consistent and replayable.
- Update `docs/ARCHITECTURE.md` and the API route table when adding the rollup endpoint.
