# Capability gaps

Phase 2 classifies all 132 closed source demands as **gap**. Phase 1 establishes
individual records, state carriers, commands, and evidence surfaces, but does
not establish an integrated user-facing capability contract for any source
demand. This is intentionally conservative: a source label, an API response
field, or an isolated command is not a current capability.

No derivation is admitted. The available evidence does not define deterministic
algorithms, typed inputs, unknown behavior, and freshness semantics for the
requested health, planning, causal, budget, comparison, or intervention claims.
Typed steering (`CAP-92`) and steering patches (`CAP-93`) are explicit gaps, not
current capabilities.

Canonical projection: `capabilities/registry.yaml` (`CAP-1` through `CAP-132`).
