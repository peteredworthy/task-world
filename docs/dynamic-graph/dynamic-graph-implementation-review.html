Dynamic Graph Implementation Review

task-world · src/orchestrator/graph/ + src/orchestrator/graph_runtime/ + src/orchestrator/workflow/graph_driver.py · ~20,700 lines · reviewed 2026-07-01
Verdict. The dynamic graph is an architecturally serious event-sourced execution kernel: a pure command/event/projection core with an effectful shell, transactional outbox, optimistic concurrency, and an unusually disciplined validation culture (FR proof ledger, product-path evidence). Its main risks are internal, not conceptual: a handful of monolithic modules, a growing dual-source-of-truth pattern where command handlers rescan the raw event log instead of the projection, recovery logic accreting into schedule_tick as reactive patches for quiescence bugs, and full-replay costs that grow with every audit event the scheduler emits. All are fixable incrementally without changing the external contract.

1. Architecture overview

The dynamic graph replaces the legacy parent/child oversight carrier with a typed work graph. A routine is compiled (graph/compiler.py) into nodes (worker, verifier, planner, check, gate, join, final_gate, recovery…) and typed edges with port contracts. Planner agents extend the graph at runtime by submitting validated patches, so the graph grows as the run discovers work — this is the "dynamic" part.

2. Strengths

Strength

Pure kernel / effectful shell separation is real, not aspirational

graph/ vs graph_runtime/ · commands.py:89 apply_command · clock.py FakeClock, SequentialIdGenerator

apply_command takes a projection, the event list, a payload, a clock, and an id generator, and returns events — nothing else. Time and identity are injected, so every scheduling, recovery, and validation decision is deterministic and replayable in-memory. This is what makes the 80 graph test files (including per-FR acceptance suites test_graph_fr02…fr17 and test_graph_outbox_crash_points.py) possible and cheap. Rejections are themselves events (command_rejected, patch_rejected), so failed intent is auditable rather than lost in exceptions.

Strength

Correct durability spine: optimistic concurrency + transactional outbox

controller.py:49–99 · store.py:467–520 · outbox.py:79–113

Every command carries an expected_position; a race raises StaleProjectionError, with the DB unique constraint on (aggregate_id, version) as a second line of defense behind the pre-check. Side-effect intent (agent_dispatch_requested, cleanup_requested) is written to outbox rows in the same transaction as the events, and the executor protocol explicitly documents the at-least-once/idempotency contract. Startup recovery (recovery.py + reconcile_runtime) resets in-flight dispatching rows and converts leases whose processes are gone into agent_died. This is the textbook pattern, implemented with the crash points actually tested.

Strength

Patch system treats planner agents as untrusted proposers

patch_validator.py · macros.py · horizon_templates.py · commands.py:_apply_patch_command

Dynamic mutation goes through a validated PatchEnvelope: role-scoped allowed ops (ALLOWED_BY_ROLE — planners cannot create gates), a read-set staleness check that classifies intervening events as invalidating or neutral, planner budgets, and macro expansion. Horizon templates give planners canonical region shapes (discovery → implementation → validation → gap analysis → corrective → final invariant) instead of freeform topology. The design assumption — LLM output is a proposal to validate, not an instruction to execute — is the right one and is applied consistently.

Strength

Resource claim model is unusually thorough

scheduler.py:89–116 claims_conflict · :238–361 path/glob overlap

Claims distinguish read/write/graph_write/review_write/external modes, snapshot-scoped reads (a read pinned to a snapshot doesn't conflict with a write), external resource keys with exclusivity, and path overlap with glob handling and repo-relative normalization that rejects ../ escapes. Deterministic tie-ordering (priority, kind, region order, creation position, node id) makes scheduling reproducible, and every deferral records a machine-readable reason (node_deferred with resource_conflict:write:write etc.), which feeds directly into the observability story.

Strength

Observability as projections, plus read models for cost

projections.py: 35+ project_* functions · store.py: event summaries, node-detail read models, projection snapshots, field-extracted light reads

/graph/final-blockers, scheduler view, lease view, decision view, planner freshness packet, residue report — the run's state is explainable from durable events, and the dogfood pause diagnosis in status.md shows these readbacks doing real diagnostic work. The store layer adds pragmatic performance escapes: JSON field extraction to avoid hydrating full payloads (read_run_light), persisted event summaries, and node-detail read models maintained incrementally on append.

Strength

Operational defense in depth

graph_driver.py:388–434, 509–521 · dispatch.py:_bounded_prompt · gatekeeper.py

The driver snapshots the main worktree's dirty set before driving and flags any leaked paths after (a direct response to the June worktree-escape incidents); prompts are size-bounded (the E2BIG fix); a signature-based no-progress guard converts silent stalls into a recoverable graph_blocked pause instead of a spinning loop; leases expire and renew; the gatekeeper classifies worktree residue against a taxonomy. Each guard traces to a real incident — the system is absorbing its operational history.

Strength

Validation culture: proof ledger over test-passing

docs/dynamic-graph/status.md · typed-work-graph-requirements.md · complete/true-comparison-results.md

FR-01…FR-18 were closed only with product-path evidence (real runs through the API/runtime surface with observable readbacks), tests explicitly demoted to regression evidence. The true-comparison study measured real cost (dynamic ≈ $0.77/run, ~3-agent-equivalent cost with structural correctness guarantees). This discipline is rare and is the reason the June dogfood found the task-region fulfillment bug at all.

W1 — Dual source of truth: handlers rescan raw events past the projection

fixed in c95793889 "Make graph projection the single read path" · residual scans: commands.py _has_passed_completion_decision, _current_passed_verification_results, _retry_backoff_deferred_reason, _cleanup_requested_event / _cleanup_applied_exists, _node_creation_position

Resolved for the named high-risk helpers. Accepted-output-record, failed-verification, and recovery-node lookups now read folded projection fields, with parity tests in tests/unit/test_graph_projections.py (per w1-single-read-path-spec.md). Residual: six small helpers still scan raw events, and command-handler signatures still accept the raw event list alongside the projection, so nothing structurally prevents the raw-scan idiom from returning. Finish per w1b-residual-raw-scans-spec.md: migrate the stragglers, then drop events from handler signatures so the type system enforces the discipline.

High

W2 — Recovery logic is accreting into schedule_tick as reactive patches (unchanged)

commands.py:2244 _apply_schedule_tick → _failed_check_recovery_events (:2441), _failed_verification_recovery_events (:2525), _passed_verification_terminalization_events (:2614), _passed_check_terminalization_events (:2646), _no_successor_recovery_terminal_failure_events (:2665)

schedule_tick is no longer a scheduler: before it schedules anything it runs five distinct repair passes that patch up states other commands should have settled. The commit history ("Recover quiescent graphs after failed checks", "Recover dynamic graph continuation after verifier failure", and post-review 5bacd79dd "fix graph runtime recovery edges") and the June dogfood pause (graph_blocked, task_not_accepted blockers on control regions) show the pattern: a lifecycle transition is missed at its source, the graph goes quiescent, and a new patch is bolted on reactively. The class of bug — "graph quiescent with non-accepted tasks" — keeps recurring because the root cause (transitions not emitted where the triggering event is applied) is untreated. All five sweeps remain as of c95793889. Spec: w2-recovery-at-source-spec.md.

High

W3 — Full replay per command, and the scheduler inflates the log it must replay (read side improved; write side unchanged)

controller.py:62–71 read_run + rebuild_projection every command · store.py invalidate_projection_snapshot on append · commands.py:2324–2431 node_deferred per tick

Partially improved: the fold-once series (8892968a5…c11b04f95) removed redundant re-folds on the read path — API views and the evidence digest now fold once (digest ~10s → ~1.8s). Unchanged: every handle_command still reads the full event stream and folds from scratch — O(n) per command, O(n²) over a run's life. The store has a projection snapshot read model, but the controller's write path never uses it, and appends invalidate the snapshot rather than folding new events into it. schedule_tick still persists node_deferred audit events on every tick for every ineligible node, so the polling drive loop grows the log even when nothing happens — inflating replay cost and forcing the driver's signature-based progress check because raw position always advances. Startup recovery still replays every run in the database. Spec: w3-incremental-snapshots-spec.md.

Medium

W4 — Monolithic modules with an if-chain dispatcher (unchanged — files grew)

commands.py 4,962 lines (+47) · projections.py 3,869 (+243) · dispatch.py 2,962 (+45) · store.py 1,797 (+53) · commands.py:91 apply_command if-chain · graph/__init__.py 368-line re-export

Four files hold ~65% of the subsystem, and every file has grown since the original review — the W1 fix added projection fields into projections.py rather than splitting it. commands.py mixes lifecycle, callbacks, patches, scheduling, joins, gates, heartbeats, and five recovery sweeps; dispatch.py mixes outbox execution, process management, prompt/packet assembly for four node roles, and hydration policy. Helper counts (150+ private functions in commands.py) make ownership of any given invariant hard to locate, and the flat __init__ re-export couples every consumer to one namespace. A small extraction has started (graph/callbacks.py, 153 lines) — the seam is viable. Spec: w4-split-monoliths-spec.md.

Medium

W5 — Stringly-typed core despite the "typed work graph" goal (edge layer improved)

projections.py:58 GraphProjection = TypedDict of dict[str, Any] maps · pervasive payload.get()/isinstance guards (_payload_string_list, _payload_truthy, _candidate_id_from_payload…)

Partially improved: 478055890 "Add typed graph edge selectors" put typed models on edges and selectors (models.py +449 lines), proving the incremental conversion path works. Unchanged elsewhere: records and node payloads have Pydantic models in models.py but are validated at the boundary and then handled as dict[str, Any] everywhere else — the projection, the reducers, and command helpers work on untyped dicts with defensive extraction helpers. Typos in payload keys, missing fields, and shape drift remain runtime phenomena discovered by tests or dogfood rather than by mypy. The _is_*_record_payload / _*_payload_for_validation shims are the visible cost. Spec: w5-typed-payloads-spec.md.

Medium

W6 — Outbox dispatcher is serial, backoff-free, and dead-ends quietly (unchanged)

outbox.py:125 max_attempts=3 · :149 immediate re-pending · :227–233 _mark_failed_attempt → OUTBOX_FAILED dead-end · spec: w6-outbox-hardening-spec.md

Dispatch claims one row per DB transaction and executes side effects strictly sequentially — independent agent dispatches for parallel-safe nodes still serialize through the dispatcher (the executor tracks concurrent processes, but rows are dispatched one at a time). A failed attempt goes straight back to pending with no backoff, so a deterministic failure burns all 3 attempts in quick succession, after which the row sits in failed with no readback, alert, or requeue path surfaced in the graph API. Recovery redispatches pending/dispatching but not failed.

Medium

W7 — Heuristic glob-overlap check can under-detect conflicts (unchanged)

scheduler.py:333–344 _literal_prefix_may_match_glob probes ("x", "x.py", "nested/x.py") · :339 _glob_prefixes_may_overlap static-prefix comparison · spec: w7-glob-overlap-spec.md

Whether a literal claim path sits "under" a glob claim is decided by probing three synthetic suffixes; a pattern whose match depth exceeds the probes (e.g. src/*/*/gen/*.py vs literal src/a) can be judged non-overlapping, letting two writers into overlapping paths — the exact safety property claims exist to enforce. Glob-vs-glob comparison falls back to static prefixes, which is conservative but returns True for any two rootless patterns, over-serializing. Empty path lists also conflict with everything, which is safe but silently defeats parallelism when a claim is sloppily specified.

Low

W8 — Drive loop is a poll loop with embedded special cases; assorted dead code (unchanged — driver grew)

graph_driver.py now 1,004 lines (was 838; +173 in 5bacd79dd) · recovery.py:62–63 no-op if not redispatched and pending_before: redispatched = [] still present

drive_to_quiescence re-ticks, re-reads the projection multiple times per iteration, renews expired leases, retries one extra recovery tick on quiescence, and compares progress signatures — workable, but it is control flow compensating for the kernel not telling the runtime when to act (a consequence of W2/W3), and the recovery-edges fix added more driver special-casing rather than less. recovery.py still carries the self-cancelling statement. The single-writer, position-serialized design is fine for current scale but is a stated ceiling for multi-process deployment. Spec: w8-drive-loop-cleanup-spec.md (do after W2/W3).

4. Recommended improvements

Ordered by leverage; 1–3 attack the recurring bug class, 4–6 are structural hygiene, 7–9 are hardening.

#ImprovementAddressesSketch
1 Make GraphProjection the single read path W1, W2, W3 Inventory every raw-event scan in commands.py; for each, add the missing derived field to the projection and fold it in reduce_event (accepted records by port, failed verifications, recovery-node index already half-exist as helpers). Then change handler signatures to take projection only — the type system enforces the discipline permanently. This is the same refactor the project's event-driven-intent note has been pointing at.
2 Move state repair out of schedule_tick to the causing command W2 Each recovery sweep exists because a callback/check acceptance didn't emit its follow-up transitions. Emit terminalization and recovery-arming events where the triggering record is accepted (_apply_callback_command), keeping one idempotent reconcile command as an explicit escape hatch instead of five implicit sweeps per tick. Kills the "graph quiescent with non-accepted tasks" whack-a-mole class at the source.
3 Incremental projection snapshots on the write path W3 The fold is already incremental (reduce_event); persist the folded projection per append (snapshot + position) instead of invalidating it, and have handle_command load snapshot + tail. Raw-scan helpers block this today — do after #1. Startup recovery should replay only non-terminal runs.
4 Stop persisting per-tick node_deferred audit events W3, W8 Keep last-deferred-reason in a read model (or emit only on reason change). Log stops growing while idle, replay cost drops, and the driver's progress-signature workaround can shrink back to "did position advance".
5 Split the monoliths along command/role seams W4 graph/commands/ package: lifecycle, callbacks, patches, scheduling, recovery — with a registry dict replacing the if-chain in apply_command. dispatch.py: separate prompt/packet assembly (pure, ~1,200 lines of it) from process execution. Mechanical, low-risk, big review-cost payoff.
6 Typed event payloads end-to-end W5 Discriminated union on event_type for EventEnvelope.payload; typed dataclass fields in the projection. Do gradually — start with the record types that already have Pydantic models and delete the _is_*_record_payload shims as each converts.
7 Outbox hardening W6 Exponential backoff with jitter on failed attempts (add next_attempt_at); batch-claim rows for parallel-safe kinds; surface failed rows in a readback (e.g. /graph/final-blockers already has the shape) plus an operator requeue endpoint.
8 Replace the glob-probe heuristic with segment analysis W7 Compare claim paths segment-by-segment treating */? segments as wildcards (and ** as multi-segment); conservative-True only for genuinely undecidable cases. Add a Hypothesis property test: overlap(a,b) must be True whenever any concrete path matches both — the current probes would fail it immediately.
9 Event-triggered driving instead of pure polling W8 After #2, the drive loop can tick on completion signals (callback accepted, lease expired, patch applied) with a slow heartbeat fallback, instead of unconditional tick-and-diff. Also delete the recovery.py no-op and prune the 355-line __init__ re-export to the actual public surface.
