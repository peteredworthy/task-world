# W5 Typed Event Payloads End To End

**Status:** Closed and independently verified

**Implemented through:** Task 13 commit `e63fb41ec`, finalized by source repairs
`b63146d9b`, `0289de70c`, and `185f31abc`

The original incremental proposal typed one payload family at a time while
preserving malformed historical event shapes. That compatibility-first approach
is superseded by the approved strict architecture cutover. Existing runs were
disposable, so Task 13 removed the replay aliases, generation-1 paths, raw
reducers/handlers, compatibility validators, and Deferred Compatibility Cleanup
Register rows D1-D6 after satisfying the database precondition.

## Implemented Architecture

- Exactly 44 event and 23 command specifications are grouped in domain-owned
  immutable tuples and composed into a deterministic, duplicate-checked
  `GraphCatalog`.
- Payloads derive from frozen, strict, `extra="forbid"` Pydantic models. There
  are no W5 `mode="before"` compatibility normalizers or catch-all top-level
  payload fields.
- Composition roots inject the catalog through compiler, controller, store,
  runtime, workflow, CLI, and API paths; there is no mutable global registry.
- Commands validate once and dispatch concrete models. Event producers create
  concrete payloads through specifications and emit `HydratedEvent` values.
- Schedule, patch, callback, lifecycle, and source-repair handlers live in their
  typed owning modules; `_commands.py` is retired. Patch operations use a
  strict discriminated `PatchOp` union.
- Persistence stores complete generation-2 `StoredEventEnvelope` JSON. Reads
  reject incompatible generations and corrupt payloads with run, position,
  event-type, and validation context, then hydrate exactly once.
- Reducers consume concrete payload models. Projection-neutral/audit events are
  cataloged explicitly and use the same create/store/hydrate path.
- Full, light, summary-rebuild, projection/checkpoint, and node-detail reads
  retain complete payloads. The four field allowlists and partial
  reconstruction logic are deleted.
- Payload-shaped projection values use concrete models; intentionally flexible
  nested business/public JSON remains explicit and named.
- Store projectors validate concrete payloads, typed payload classes declare
  node references, and atomic forward-reference batches remain supported.
- AST architecture checks, deterministic metrics, codemod idempotency,
  change-spread contracts, and pre-commit enforcement prevent regression.

## Reconciled Original Scope

inputs. The one-family tolerance strategy, compatibility validators and aliases,

file-state, gatekeeper, and cleanup closed through Tasks 5-8; Task 11 superseded
allowlist generation by deleting the lists; Task 13 superseded legacy
