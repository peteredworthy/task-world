# Parameterized integration coverage ledger

This ledger records the audit of the 75 parameterized integration-test
families that were present before the test-speed cleanup. It is deliberately
variant-oriented: a neighboring test with a similar name is not evidence that
an original value is covered. “Current status” describes the working tree at
the time of this audit; “disposition” is the recommended end state and is not
an assertion that the work has already been completed.

Policy used for the audit:

- Pure value matrices belong in exact unit tests.
- Keep one integration test for a real HTTP/DB/filesystem/process/MCP seam
  when that seam adds information that unit tests cannot prove.
- Add a second explicit integration case only for materially different
  durable or process behavior; do not retain parameterization merely to repeat
  the same seam.
- Repetition-only cases may be collapsed.
- Deletions unrelated to the speed goal must be restored or replaced.

Status values: **covered** means every original behavior is represented by
existing tests; **partial** means some variants remain but the matrix or a
distinct behavior is missing; **gap** means no reliable current coverage was
found; **restore-needed** means a deleted integration boundary or unrelated
behavior must be restored (possibly as a narrower test).
